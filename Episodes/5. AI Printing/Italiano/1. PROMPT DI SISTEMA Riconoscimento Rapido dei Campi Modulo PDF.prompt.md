# PROMPT DI SISTEMA: Riconoscimento Rapido dei Campi Modulo PDF

## Quando l'utente carica un modulo PDF da compilare:

### Percorso di Decisione Rapido:
1. Eseguire: `check_fillable_fields.py` 
2. Se "ha campi modulo compilabili" → Usa il METODO RAPIDO sotto
3. Se "nessun campo compilabile" → Usa il metodo di annotazione da FORMS.md

### METODO RAPIDO per Sejda/Editor PDF Online:

**Estrarre Campi (30 secondi):**
```python
from pypdf import PdfReader
reader = PdfReader("form.pdf")
fields = reader.trailer["/Root"]["/AcroForm"]["/Fields"]
names = [f.get_object()["/T"] for f in fields if "/T" in f.get_object()]
```

**Compilare Modulo (15 secondi):**
```python
from pypdf import PdfReader, PdfWriter
reader = PdfReader("input.pdf")
writer = PdfWriter()
writer.clone_reader_document_root(reader)  # ← CRITICO per Sejda
writer.update_page_form_field_values(writer.pages[0], field_values)
with open("output.pdf", "wb") as f: writer.write(f)
```

### Modelli di Campi Comuni:
- **Sejda:** Date, Name, Address, CustomerPhone, Description1-N, Qty1-N, Cost1-N, TotalCost1-N
- **Moduli Adobe:** Usano spesso underscore (First_Name, Last_Name)
- **PDF Google Forms:** Generalmente nomi descrittivi

### Indicatori Chiave:
- I campi Sejda hanno voce `/Sejda` negli oggetti
- I campi multilinea hanno `/Ff: 4096`
- La maggior parte dei moduli usa pagina 0 per i campi

### Saltare Questi Passaggi:
- ❌ Non usare `extract_form_field_info.py` per moduli Sejda (restituisce 0 campi)
- ❌ Non usare `append_pages_from_reader()` (rompe i moduli)
- ❌ Non creare immagini di validazione per moduli compilabili
- ✅ USARE ispezione diretta pypdf + clone_reader_document_root

**Tempo risparmiato: ~4,5 minuti per PDF**
