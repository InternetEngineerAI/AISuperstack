## Lorsque l'utilisateur télécharge un formulaire PDF à remplir :

### Chemin de Décision Rapide :
1. Exécuter : `check_fillable_fields.py` 
2. Si "a des champs de formulaire remplissables" → Utiliser la MÉTHODE RAPIDE ci-dessous
3. Si "pas de champs remplissables" → Utiliser la méthode d'annotation de FORMS.md

### MÉTHODE RAPIDE pour Sejda/Éditeurs PDF en Ligne :

**Extraire les Champs (30 secondes) :**
```python
from pypdf import PdfReader
reader = PdfReader("form.pdf")
fields = reader.trailer["/Root"]["/AcroForm"]["/Fields"]
names = [f.get_object()["/T"] for f in fields if "/T" in f.get_object()]
```

**Remplir le Formulaire (15 secondes) :**
```python
from pypdf import PdfReader, PdfWriter
reader = PdfReader("input.pdf")
writer = PdfWriter()
writer.clone_reader_document_root(reader)  # ← CRITIQUE pour Sejda
writer.update_page_form_field_values(writer.pages[0], field_values)
with open("output.pdf", "wb") as f: writer.write(f)
```

### Modèles de Champs Courants :
- **Sejda :** Date, Name, Address, CustomerPhone, Description1-N, Qty1-N, Cost1-N, TotalCost1-N
- **Formulaires Adobe :** Utilisent souvent des traits de soulignement (First_Name, Last_Name)
- **PDFs Google Forms :** Généralement des noms descriptifs

### Indicateurs Clés :
- Les champs Sejda ont une entrée `/Sejda` dans les objets
- Les champs multilignes ont `/Ff: 4096`
- La plupart des formulaires utilisent la page 0 pour les champs

### Ignorer Ces Étapes :
- ❌ Ne pas utiliser `extract_form_field_info.py` pour les formulaires Sejda (renvoie 0 champs)
- ❌ Ne pas utiliser `append_pages_from_reader()` (casse les formulaires)
- ❌ Ne pas créer d'images de validation pour les formulaires remplissables
- ✅ UTILISER l'inspection directe pypdf + clone_reader_document_root

**Temps économisé : ~4,5 minutes par PDF**
