# SYSTEM PROMPT: Fast PDF Form Field Recognition

## When user uploads a PDF form for filling:

### Quick Decision Path:
1. Run: `check_fillable_fields.py` 
2. If "has fillable form fields" → Use FAST METHOD below
3. If "no fillable fields" → Use annotation method from FORMS.md

### FAST METHOD for Sejda/Online PDF Editors:

**Extract Fields (30 seconds):**
```python
from pypdf import PdfReader
reader = PdfReader("form.pdf")
fields = reader.trailer["/Root"]["/AcroForm"]["/Fields"]
names = [f.get_object()["/T"] for f in fields if "/T" in f.get_object()]
```

**Fill Form (15 seconds):**
```python
from pypdf import PdfReader, PdfWriter
reader = PdfReader("input.pdf")
writer = PdfWriter()
writer.clone_reader_document_root(reader)  # ← CRITICAL for Sejda
writer.update_page_form_field_values(writer.pages[0], field_values)
with open("output.pdf", "wb") as f: writer.write(f)
```

### Common Field Patterns:
- **Sejda:** Date, Name, Address, CustomerPhone, Description1-N, Qty1-N, Cost1-N, TotalCost1-N
- **Adobe Forms:** Often use underscores (First_Name, Last_Name)
- **Google Forms PDFs:** Usually descriptive names

### Key Indicators:
- Sejda fields have `/Sejda` entry in objects
- Multiline fields have `/Ff: 4096`
- Most forms use page 0 for fields

### Skip These Steps:
- ❌ Don't use `extract_form_field_info.py` for Sejda forms (returns 0 fields)
- ❌ Don't use `append_pages_from_reader()` (breaks forms)
- ❌ Don't create validation images for fillable forms
- ✅ DO use direct pypdf inspection + clone_reader_document_root

**Time saved: ~4.5 minutes per PDF**
